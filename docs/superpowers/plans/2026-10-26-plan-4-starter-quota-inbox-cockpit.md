## Global Constraints

- Python 3.9+ standard library only. Tests: `python3 -m unittest discover -s tests -v` from the repo root; model-free and hermetic. No test reads the developer's real Orca dir, `~/.cc-switch`, metrics log, or state: `BW_STATE_DIR`, `BALANCEWHEEL_METRICS_LOG`, `BALANCEWHEEL_CONFIG`, and the new `BW_ORCA_SUPPORT` (Orca's support dir) and `BW_CCSWITCH_DIR` (`~/.cc-switch`) point at temp dirs. Anything that spends model quota lives in `tests/attack/` and is not in `unittest discover`.
- Clean-room; synthetic fixtures only (`tests/fixtures/orca/`, `tests/fixtures/openrouter/`, `tests/fixtures/ccswitch/`), hand-written from the shapes this plan states — never captured output, account names, paths, or values.
- Every external surface (Orca, cc-switch, agy, OpenRouter, Terminal, a tool's update command) absent, slow, or malformed → `unknown` (or `skipped`) with a one-line reason. `bw start` and `bw status` never raise on one; a missing field is `unknown`, never a `KeyError`. Every shell-out goes through `lead.proc.run` (or a `run=` parameter defaulting to it) — including `containment.verification_key`/`_first_line`, `containment.guard_key`, and `projects.resolve_project` (Task 1); every HTTP call through a `fetch=` parameter. No retry loops anywhere.
- No credential is read by bw. The OpenRouter key comes from the environment variable the config names, is sent only to `https://openrouter.ai/api/v1/key` (no redirects followed), and never appears in a file, log line, error, or exception message. (The same variable already reaches leads through their inherited environment — pi leads on OpenRouter need it; that is not a bw read and this plan does not change it.)
- Copies of third-party databases bw reads live only in `state_dir/sealed/` (0700), which every sandbox profile denies reading (Task 0a). bw writes inside a lead-writable directory (`handoffs/<worktree-key>/`) never; it reads from one only with `lstat` first, then `O_NOFOLLOW | O_NONBLOCK`, regular files, a size cap (the existing `launch.read_markers` / `handoff.read_checkpoint` pattern). Anything bw writes *for* a lead lives in a bw-owned directory the lead may only read.
- Model ids, plan, lead, and profile names are data; nothing in an interface names one. Orca provider names (`claude`, `codex`, `kimi`, `antigravity`, …) are config values, not constants in code.
- **Verification keys reset once, at the start.** All `lead/sandbox.py` changes in this plan land in Task 0a (containment key: pi and Kimi need `bw sandbox verify`); the `SECRET_READS` addition there changes `rules_version`, and Task 1's edits to `lead/guard/review.py` and `lead/guard/verify.py` change `guard_version` — run Task 1 directly after 0a and re-verify once after both (`bw sandbox verify pi|kimi`, `bw guard verify pi`; the user's runs, quota). No later task touches `sandbox.py`, `runtimes.py`, or `lead/guard/`, except the gated Task G.
- CHANGELOG `[Unreleased]` in the same commit as any change to the config schema, the log schema, `setup/paths.txt`, or a `bw` subcommand's contract. Commits: lowercase `feat:`/`fix:`/`test:`/`docs:`. `bin/bw`'s docstring is its help text and lists every subcommand.

## Design decisions (binding)

1. **Three phases, one plan** (user's decision 1). **cc-switch is adopted** as the usage-and-cost source for the Usage view (user's decision 2): its database read-only; routing, failover, aggregation, Codex provider management, and every config, prompt, MCP, and skill sync stay off; Orca stays the only canvas quota source and cc-switch is never a quota source. Both land as named spec amendments and in `docs/stack.md` in Task 0b, the first commit whose code relies on decision 2.
2. **One shell-out helper.** `lead/proc.py`: `Result = namedtuple("Result", "rc out err timed_out")`; `run(argv, timeout, cwd=None, env=None, stdin=subprocess.DEVNULL) -> Result` — stdout and stderr go to temp files (not pipes, so a grandchild that keeps a pipe open after the kill cannot hang the read), `Popen(start_new_session=True)`, `wait(timeout)`, on timeout `os.killpg(SIGKILL)` and `Result(124, out, err, True)`; `FileNotFoundError`/`PermissionError` → `Result(127, "", "<argv0>: not found", False)`. Never a shell. Every module takes `run=proc.run`.
3. **Snapshot files.** The statusline keeps writing `state_dir/quota/<plan>.json` (no change for a statusline process already running); every other source writes `state_dir/quota/<plan>.<source>.json`, `source ∈ {"probe", "orca"}`. Plan names match `[a-z0-9-]+`, so the first `.` splits plan from source; the legacy `read_quota(state)` ignores dotted names. Probe bookkeeping (Orca shape record, OpenRouter month baseline, agy's working dir) lives in `state_dir/probes/`, never in `quota/`.
4. **Windows and pools are arbitrated separately.** Account-wide windows, in precedence order per plan: `quota: "statusline"` → `[statusline]`; `quota: "probe"` → `[probe, orca if orca_provider]`; `quota: "orca"` → `[orca]`; `quota: "none"` → nothing; the first source whose snapshot is known and fresh wins. Orca's *percentages* never drive decisions on a statusline plan: with `orca_provider` set they ride along as `cross_check` (shown, never chosen). Pools (`orca_windows`) come from the freshest known, non-stale Orca snapshot *whatever source won the windows*, so a Claude plan read from the statusline still sees its Fable-only pool. This reconciles the spec's precedence with "bw does not use Orca's Claude numbers for decisions" and is recorded as an amendment.
5. **No network probe mid-session; a local Orca re-read is allowed.** Network probes (OpenRouter; agy after Task G) run at `bw start` step 4, when `bw lead` starts (before its first decision) and at its session boundary, and on `bw probe`; `probes.refresh` joins all its threads before returning. In the poll loop, every `probe_every_min`, `bw lead` re-reads Orca's local cache synchronously (`orca account list --json`, no thread, 10 s cap) and writes the Orca snapshots — display and freshness only; the running decision still acts on caps alone, so no reading ever triggers a switch.
6. **Freshness.** `orca` and `probe` snapshots older than `2 × probe_every_min`, or with `observed_at > now + 300`, are unknown (`"stale: observed <n> min ago"` / `"observed in the future"`). Statusline snapshots keep today's rule (`rotation.effective_quota`: unknown once past a window's reset). Every unknown snapshot carries `last_known_at` (copied forward from the previous file of the same source), so "no quota reading since <t>" survives.
7. **Orca readings never create or extend a cap**, and a pool never takes out a plan. `plans.*.orca_windows` maps a pool to lead or seat names; the snapshot carries it under `pools`. `rotation.decide` treats a lead named in a full pool (`used_pct ≥ 100`, reset in the future) as not startable at `start`/`boundary`, and — when a cap forces a mid-session switch — skips it as a replacement candidate; a pool alone never triggers a switch. Seats in pools are shown in the registry (no seat code in this repo).
8. **Expired caps are cleared by bw, not by a reading.** A cap record past its `resets_at` is removed by `quota.clear_expired_caps` once a fresh known windows reading exists for the plan from any source, else at `resets_at + cap_expiry_hours`. Without this, a plan capped once and read by Orca afterwards stays blocked until its remaining crosses `return_above_pct`, because only the statusline clears caps today. Removing an *expired* record is not "Orca clears a cap": an unexpired cap is never touched by a reading. Recorded as an amendment.
9. **Copy, then read, into a sealed dir.** `lead/sqlite_ro.py` copies `db` and `db-wal` (when present; never `-shm`, which SQLite rebuilds) into a fresh `mkdtemp(dir=state_dir/sealed)` (0700), opens the copy, sets `PRAGMA query_only = ON`, runs a callback, and removes the copy in a `finally`. Reasons: a direct `mode=ro` open of a WAL database still writes `-shm` (and creates `-wal`/`-shm` when absent), and a direct read-only open of Orca's DB already failed on the author's machine; a copy makes "bw never writes their files" provable by test; and copies in `$TMPDIR` would be readable by a lead whose scratch is a sibling there (sandbox-exec allows reads by default). A database over 256 MiB is `unknown` ("too large to snapshot"); a `sqlite3.DatabaseError` on the copy is `unknown` ("snapshot inconsistent; the app was writing — refresh again"), no retry.
10. **The inbox crosses the sandbox by files, in two directions with different owners.** *Asks* — the lead publishes each ask as one complete file: write `$BW_ASKS/.tmp-<random>`, then rename to `$BW_ASKS/<random>.ask` (`BW_ASKS` = `handoffs/<worktree-key>/asks/`, lead-writable). bw ingests only `*.ask` names that `lstat` as regular files, opens them `O_NOFOLLOW | O_NONBLOCK`, records each, then unlinks it; the ask `id` is `sha1(name + content)[:8]`, so a crash between record and unlink re-ingests to the same id and dedupes; bw rescans at session start and drains once more after the child exits, before `build_handoff`, and at session end, under the outgoing session's identity. Ingest never raises (`OSError` → one notice). *Answers* — `state_dir/inbox-view/<worktree-key>.md` (`BW_INBOX`), a bw-owned file outside every write grant and read-granted to bw-contained leads (Task 0a), holding **only answers** (ask id + the user's answer text), never ask text, so everything in it is the user's words. bw rewrites it after each `bw answer` and at session start. `bw inbox --project` serves runtimes and users that can run bw. Metrics get `ask`/`answer` events without text; the text lives only in `inbox.jsonl`.
11. **`bw start` opens a workspace one way per environment.** It first refuses when bw's own real path lies inside the target worktree or its common git dir (a lead could edit the next `bw lead`). Orca running (`orca status --json` → `result.app.running is True`): `["orca", "terminal", "create", "--worktree", f"path:{worktree}", "--title", f"{basename(worktree)} lead", "--command", cmd]`, where `cmd` = `shlex.join(["env", *assignments, bw, "lead"])`, `bw` the real path of the running `bin/bw` and `assignments` = `BALANCEWHEEL_CONFIG=…` and `BW_STATE_DIR=…` for those set in bw's environment. Otherwise: write `state_dir/start/<worktree-key>.command` (mode 0700; `#!/bin/sh`, one quoted `export` per assignment, `cd <quoted worktree> || exit 1`, `exec <quoted bw> lead`) and run `["open", "-a", "Terminal", <file>]`. No `osascript`. The file sits outside every lead write grant. A worktree whose lock is held is not opened again.
12. **Re-verification is independent of updates.** After the update phase — or at once with `--no-update` — bw enumerates every runtime any configured lead uses, recomputes its containment key (runtimes contained by bw) and guard key (guarded leads; agy only once Task G flips `AGY_SPIKE_PASSED`), and re-runs `bw sandbox verify` / `bw guard verify` for each key that no longer matches, on a worker pool with one worker per runtime (a runtime's work is submitted when its tool's update finishes, or immediately when it has none). A test that cannot run is `pending` with its reason: the lead's plan is capped, `--no-verify`, the tool's version after the update is `"unreadable"`, or agy awaits Task G. Seat keys wait for `bin/seat`; until then the registry shows seat verification from `state_dir/seats.json` when present, else `unknown`. Results go to `state_dir/start.json`.
13. **Runtime locks are keyed by runtime.** `state_dir/locks/runtime-<runtime>.lock`. A tool maps to a runtime through `tools.<t>.runtime`, else `DEFAULT_TOOL_RUNTIME = {"claude": "claude-code", "codex": "codex", "agy": "agy", "pi": "pi", "kimi": "kimi"}`; `NON_RUNTIME_TOOLS = {"orca", "cc-switch"}` update with no lock. Any other tool with no resolvable runtime is not updated (`skipped: no update lock — set tools.<t>.runtime`), and a lead runtime no tool maps to prints `no update lock for runtime <r>`. `bw lead` takes a shared flock on its lead's runtime lock **before** `_verified` and holds it through launch and the session, passed to the child in `pass_fds` (its life follows the lead, as the worktree lock does). The updater takes `LOCK_EX | LOCK_NB`; held → `skipped-locked`. So an update can land neither between a verification check and the launch it allows, nor under a running lead.
14. **Verification records what was attacked.** `lead/verify.py` computes the key before running the attack and records a pass only if the key recomputed afterwards is identical (else `failed: key changed during the attack`).
15. **Tools serialise per installer.** `installer_of(tool_cfg)` = `basename(update[0])`, `""` without `update`; tools sharing one run one after another; installers run in parallel (`ThreadPoolExecutor`, one worker per installer). Per-tool `timeout_s` (default 600) for updates, 10 s for version reads. Progress is one line per tool as it finishes (the spec's "one live status line per tool", without terminal redraws — amendment).
16. **Versions** come from, in order: `tools.<t>.version` (argv), the adapter's `version_argv` for the tool's runtime, `tools.<t>.app` (`Contents/Info.plist` → `CFBundleShortVersionString` via `plistlib`), else `"unreadable"`. Orca (`self_updating: true`) is version-only; its version change is recorded and every mapped provider is shape-checked before the next Orca reading is trusted.
17. **No config schema bump.** New keys are additive and optional on schemas 2 and 3: `plans.*.orca_provider`, `plans.*.orca_windows`, `plans.*.probe` (`"agy" | "openrouter"`; default from `vendor`: `google` → `agy`, `openrouter` → `openrouter`), `plans.*.key_env` (default `"OPENROUTER_API_KEY"`), `tools.*.{runtime, timeout_s, version, app, self_updating}`, `cockpit.port`. `quota` gains `"orca"`. Unknown keys under `tools.*` and `cockpit` produce a warning (resolved config gains `warnings: [str]`, printed once by `bw` on stderr), not an error.
18. **The cockpit is never started by `bw start`**; step 7 prints the `bw cockpit` hint. The cockpit's one-time token is single-use (exchanged under a lock) and distinct from the cookie secret. Cookies are not port-isolated (RFC 6265 §8.5), so every sandbox denies loopback connections to the cockpit port as well as the canvas ports (Task 0a).
19. **Usage rows.** Detail from `proxy_request_logs` where `data_source != 'proxy'`, tool from `DATA_SOURCE_TOOL` (`session_log` → `claude`, `codex_session` → `codex`, `gemini_session` → `gemini`, `pi_session` → `pi`, `kimi_session` → `kimi`, `agy_session` → `agy`; any other non-proxy source → its own name, flagged `unmapped`); errors are rows with a non-null `status_code` outside 200–299. Older days from `usage_daily_rollups` (no `data_source`; tool from `app_type`, flagged `rollup`; errors = `request_count − success_count`). cc-switch rolls a day up and prunes those detail rows in one step, so the two never hold the same row. `created_at` is epoch seconds (v4.0.20 source). Costs are TEXT decimals parsed with `decimal.Decimal`; a group with any unparseable cost shows cost `unavailable`, never a partial sum, never zero.
20. **What the Leads table shows now.** Per lead (runtime + model): sessions, lead minutes, switches away on a cap, overrides (a `lead` event with reason `override`, emitted when `--use` changes the starting lead), ratings good/bad, inbox asks. The spec's task-based dimensions (throughput per task, defects, escapes, clean work, moderation quality) need `task` events and `panel.subject`; their columns read "needs task events (later step)". Counts with n; no composite.

## Review Focus

- **Orca updates itself and its JSON changes shape** — a renamed or retyped key in one provider makes the plans mapped to *that* provider `unknown` with "Orca <version> changed shape: <path>", other providers keep working, `bw status` says rotation is on observed caps only for the affected plans, and nothing raises. Test in Task 10.
- **`bw start` in a worktree that already has a lead** (an Orca pane left open) — no second pane or tab; it prints the holder (lead, pid, since) and still runs updates, verify, and probes. Test in Task 6.
- **A lead writes something hostile where bw reads** — an `.ask` that is a symlink to a secret, a FIFO, a directory, 10 MiB, control characters, a half-written `.tmp-*`, 500 asks — nothing hangs, nothing outside the dir is read, text shows escaped everywhere bw prints it, at most 50 asks per session plus one notice, and the lead cannot write the answers view. Test in Task 12.
- **The OpenRouter key is missing, wrong, redirected, or the network is down** — the plan is `unknown` with "key env OPENROUTER_API_KEY unset" / "HTTP 401" / "redirect refused" / "timeout", and the key's value appears in no output, file, exception, or request to another host. Test in Task 11.

Tests in Tasks 0a and 15.

```python
ORDER = {"statusline": ["statusline"], "probe": ["probe", "orca"], "orca": ["orca"], "none": []}
def _fresh(src, snap, now, probe_every_min):          # -> reason or None
    if not snap: return "no reading"
    if snap.get("unknown"): return snap.get("reason", "unknown")
    t = snap.get("observed_at")
    if not isinstance(t, (int, float)): return "no observed_at"
    if t > now + 300: return "observed in the future"
    if src != "statusline" and now - t > 2 * probe_every_min * 60: return "stale"
    if rotation.effective_quota(snap, now) is None: return "past its reset"
    return None
def arbitrate(sources, plan_cfg, now, probe_every_min):
    orca_ok = bool(plan_cfg.get("orca_provider"))
    orca = sources.get("orca") if orca_ok else None
    pools = orca.get("pools", []) if orca and not _fresh("orca", orca, now, probe_every_min) else []
    cross = orca if plan_cfg["quota"] == "statusline" and orca else None
    reasons, last_known = [], None
    for src in [s for s in ORDER[plan_cfg["quota"]] if s != "orca" or orca_ok]:
        snap = sources.get(src) or {}
        lk = snap.get("last_known_at") if snap.get("unknown") else snap.get("observed_at")
        last_known = max(filter(None, [last_known, lk]), default=None)
        why = _fresh(src, snap, now, probe_every_min)
        if why:
            reasons.append(f"{src}: {why}"); continue
        return dict(snap, source=src, age_s=now - snap["observed_at"], pools=pools, cross_check=cross)
    return {"unknown": True, "source": None, "last_known_at": last_known, "pools": pools, "cross_check": cross,
            "reason": "; ".join(reasons) or f"quota: {plan_cfg['quota']}"}
```

### Task 17: The cockpit server and its security

**Files:** Create `cockpit/__init__.py`, `cockpit/server.py`, `cockpit/page.html` (a stub body for now); Modify `metrics/config.py` (`cockpit.port`), `bin/bw` (`cockpit`), `CHANGELOG.md`; Test `tests/test_cockpit_server.py`.

**Interfaces:**
- Config: `cockpit.port` int 1024–65535, default 8765 (the sandbox already denies the configured port, Task 0a; changing it changes the containment key, so README says to re-verify); unknown `cockpit.*` keys warn.
- `server.make_server(port, views: dict, page: str) -> (ThreadingHTTPServer, token)` bound to `127.0.0.1`; `views` maps `/api/<name>` to a zero-argument callable returning JSON-able data.
- Request handling (the exchange is not determined by tests alone):

```text
any method but GET          → 405, Allow: GET
Host not in {127.0.0.1:<port>, localhost:<port>}  → 421
GET /?t=<token>  → under a threading.Lock: if the token is unused and compare_digest matches,
     mark it used; 303 Location: /  Set-Cookie: bw_cockpit=<secret>; HttpOnly; SameSite=Strict; Path=/
     (<secret> = secrets.token_urlsafe(32), generated at start, never the token); else 403
cookie bw_cockpit != secret (compare_digest)      → 403, text "open the cockpit with `bw cockpit`"
GET /           → page with a fresh nonce substituted for {{NONCE}}
GET /api/<v>    → JSON (view raising → 200 {"available": false, "reason": "<Exception name>"})
other path      → 404
every response  → Content-Security-Policy: default-src 'none'; script-src 'nonce-N';
                  style-src 'nonce-N'; connect-src 'self'; img-src 'self' data:;
                  base-uri 'none'; form-action 'none'; frame-ancestors 'none'
                  Referrer-Policy: no-referrer, X-Content-Type-Options: nosniff,
                  Cache-Control: no-store; no Access-Control-* header ever
```

- `bw cockpit [--port N] [--no-open]` — builds views (Task 18), serves until Ctrl-C; opens `http://127.0.0.1:<port>/?t=<token>` with `["open", url]` through `proc.run` unless `--no-open` (then prints it); port in use → one-line error, exit 1.

## Rulings taken while planning

Decision — why — cost if wrong. *[changed: gNN]* marks a ruling the plan panel changed; *[new: gNN]* one it added.

1. **Amendments for both user decisions land in Task 0b** (the cc-switch settings code), not the Phase 6 Usage task — 0b is the first code that exists only because cc-switch was adopted — cost: if adoption is rejected, 0b's commit carries docs to revert.
2. **Statusline file name unchanged; other sources get `<plan>.<source>.json`** — a statusline process started before the upgrade keeps working and its tests stay green — cost: one asymmetric name.
3. *[changed: g08]* **Orca's percentages on a statusline plan are `cross_check` only; Orca's pools apply whatever source won the windows** — satisfies both "statusline → Orca precedence" and "Orca's Claude numbers are not used for decisions", while letting a Fable-only pool exclude the leads mapped to it — cost: when Claude's statusline goes silent (#45133), rotation has no Claude percentage even though Orca has one.
4. *[changed: g43]* **No network probe mid-session; a synchronous local Orca re-read each `probe_every_min`** — network probes add nothing rotation may act on mid-session; the Orca read is local, threadless, and display-only — cost: OpenRouter spend in `bw status` ages during long sessions until `bw probe`.
5. *[changed: g01]* **Copy (db + wal, never shm) into `state_dir/sealed/`, read with `query_only`; every sandbox denies `sealed/`** — a direct read-only open of a WAL DB writes `-shm` and failed on Orca's; copies in `$TMPDIR` would be readable by leads — cost: a copy per refresh (bounded at 256 MiB) and an occasional inconsistent-snapshot `unknown`.
6. *[changed: g02, g03, g04]* **Asks are published as one complete file each and drained at every boundary; answers live in a bw-owned, answers-only view the lead can only read** — a nono-contained lead cannot run `bw` or write `inbox.jsonl`, an appended file races its reader, and a view in a lead-writable dir is forgeable for the whole session — cost: asks surface up to ~1 s late, and the lead sees answers but not its own ask text in the view.
7. **Metrics `ask`/`answer` events carry no text** — scoring needs counts; text stays in one file the user backs up — cost: the cockpit cannot show ask text from the metrics log alone.
8. *[changed: g24]* **Terminal fallback via a `.command` file and `open -a Terminal`; both launch paths pass `BALANCEWHEEL_CONFIG`/`BW_STATE_DIR` when set; bw refuses to start from inside the target worktree** — argv only, testable, and the pane runs the same config — cost: Terminal.app only (iTerm users get Terminal, or `--dry-run` prints the command).
9. *[changed: g42]* **No config schema bump; unknown `tools.*`/`cockpit` keys warn** — every new key is optional and additive — cost: a config using the new keys makes an older `bw` fail with "unknown key"; a typo'd key is only warned about.
10. *[changed: g11]* **No agy `/usage` parser until Task G sees the real shape; the google plan reads Orca's `antigravity` entry meanwhile** — no readable schema exists, and a guessing parser could read the wrong field as quota — cost: the google plan depends on Orca (unknown without it) until Task G.
11. *[changed: g10]* **OpenRouter monthly spend: `usage_monthly` when present; otherwise a month-start baseline, with the budget window omitted until a full month is covered** — the all-time `usage` field cannot say what was spent earlier this month — cost: without `usage_monthly`, the first partial month has no budget window.
12. *[changed: g18, g20]* **The budget becomes a quota window (none when the budget is 0); the key limit is display-only** — the budget resets monthly and lets the low-at-start rule skip a nearly spent lead; the key limit has no reset, so a window would block forever — cost: a budget at 95 % skips that lead at start even when the user would accept the spend.
13. *[changed: g12]* **Re-verify runs model attacks inside `bw start` for every lead runtime whose key changed, with or without updates**, with `--no-verify` to defer — cost: a start after a pi or Kimi update, or after a sandbox change, spends cents and minutes.
14. *[changed: g05, g06]* **Runtime locks keyed by runtime, mapped from tools by `tools.<t>.runtime` or a default map; taken before the verification check and held through the session; an unmapped tool is not updated** — a lock that misses the verification-to-launch window, or a tool named differently, would let an update land under a verified-but-stale binary — cost: an unmapped tool needs one config key before `bw start` updates it.
15. **Standout panel = a confirmed critical/major finding in a group no other seat shared** — the spec's "unique confirmed finding at major or above", read from `findings_detail.group` — cost: panels without `findings_detail` never count.
16. *[changed: g14]* **Leads table ships with the measured columns only, now including `override` events** — task events and `panel.subject` are not built — cost: the cockpit cannot yet answer "does agy-hosted Opus lead as well as Claude Code" beyond session counts, minutes, caps, overrides, ratings, and asks.
17. **Registry `auth` is always `unknown`** — bw reads no credential — cost: a signed-out CLI shows only through a failed update or verify.
18. **The cockpit's view errors return 200 with `available: false`** rather than 500 — one bad source must not blank the page — cost: an error is visible only as the reason string.
19. *[new: g13]* **bw clears an expired cap record once a fresh known reading exists, else after `resets_at + cap_expiry_hours`** — otherwise a plan capped once and read only through Orca stays held until its remaining crosses `return_above_pct` — cost: a plan returns on a reading below the return threshold (the start-time low-quota rule still applies).
20. *[new: g16]* **Every sandbox denies loopback connections to the cockpit port** — cookies are not port-isolated, so a dev server a lead runs on another loopback port receives the cockpit cookie when the user's browser visits it; denying the cockpit port means the lead cannot use what it captured (the one-time token never reaches a lead) — cost: changing `cockpit.port` changes the containment key and needs a re-verify.
21. *[new: g15]* **Orca shape checks are per mapped provider** — one malformed provider must not take every Orca plan to unknown — cost: a change that affects all providers is reported once per provider.
