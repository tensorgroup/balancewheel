# Plan 3 — `bw guard` v0 (rules only, shadow) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

*Written 2026-10-25; revised the same day after a deep four-seat plan review (Astra, an Opus 5.5 stand-in for the Fable seat, Kimi, DeepSeek Flash; Argon absent on Google's quota). 73 raw findings, 35 after dedupe; one refuted (pi's `--no-extensions` does not disable an explicit `-e`). Folded in, not appended. Build-order step 1 of the guard spec only: no judge model, no redaction before a model request, no circuit breaker, no `bw guard eval`, no acting mode for real leads.*

**Goal:** agy and pi leads run without permission prompts while a rules-only guard broker inside `bw lead` decides every tool call in shadow, logs it to `state_dir/guard.jsonl`, and lets the user audit decisions (including sampled allows) with `bw guard review`. Claude and Codex leads get their native autonomous modes through config schema 3.

**Architecture:** A `lead/guard/` package: a pure lexer and rules engine with a per-runtime normaliser, a JSONL record module, and a broker (unix socket in a directory no lead can write, one JSON request and reply per call) that `bw lead` runs outside the lead's sandbox. The in-runtime pieces are thin clients, copied at session start into that same lead-unwritable directory, that forward the raw tool call and return the broker's answer: a stdlib Python hook for agy, a TypeScript extension for pi loaded with `-e`. Autonomy is config (`leads.*.autonomy`) mapped to flags by the runtime adapters.

**Tech Stack:** Python 3.9+ standard library only (no `X | None` annotations); the pi extension in TypeScript using only `node:` builtins and erasable type syntax (so `node --experimental-strip-types` runs it in tests, Node ≥ 22.6; installed 22.14); `/bin/bash` 3.2 for the attack script; `unittest`.

**Spec:** `docs/superpowers/specs/2026-10-25-bw-guard-design.md` — "The trust boundary", "Autonomy per lead", "The decision path" steps 1 and 3, "Shadow, acting, audits", "Verification by attack", "Logging and privacy", "Build order" step 1, "Amendments to earlier documents". Background: `docs/superpowers/specs/2026-10-24-profiles-lead-rotation-cockpit-design.md` ("The sandbox", "The inbox", amendments), `docs/orca.md`. Where this plan departs from the spec, the departure is named in "Design decisions" and Task 10 records it in the spec.

## Global Constraints

- Python 3.9+ standard library only. Tests: `python3 -m unittest discover -s tests -v` from the repo root; the suite stays model-free and hermetic: no test reads the developer's real `~/.gemini`, `~/.pi`, or metrics log (`BW_AGY_HOOKS`, `BW_PI_AGENT_DIR`, `BW_STATE_DIR`, `BALANCEWHEEL_METRICS_LOG` point them at temp files).
- Clean-room; synthetic fixtures only (`tests/fixtures/guard/` is hand-written from the shapes Task 1 observes — never a captured payload, path, or command from a real session).
- The guard never writes inside a repo. It writes `state_dir/guard.jsonl`, `state_dir/guard-verify.json`, `state_dir/guard/<worktree-key>/` (socket and client copies), `handoffs/<worktree-key>/guard-unreachable` (written by hooks), and — only on `bw guard install agy` — `~/.gemini/config/hooks.json` (already in `setup/paths.txt`).
- Hook decisions only ever come from the broker. No `allow-once` command, no approval path the agent can reach.
- Combined decision across shell segments is the strictest: `block > ask > allow`. Unknown, unparseable, or unexpanded input never reaches `allow` by rule.
- Socket-using tests root their state at `tempfile.mkdtemp(dir="/tmp")`, never the inherited macOS `$TMPDIR` (the socket path limit is 103 bytes).
- Model ids are data; nothing in an interface names one.
- CHANGELOG `[Unreleased]` in the same commit as any change to the config schema, the log schema, or `setup/paths.txt`. Commits: lowercase `feat:`/`fix:`/`test:`/`docs:`; `bin/bw`'s docstring is its help text and lists every subcommand.
- Changing `lead/runtimes.py` (Task 6) — or `lead/sandbox.py`, if Task 5 finds nono needs a socket rule — changes the containment verification key: pi and Kimi leads need `bw sandbox verify` again (spends quota; the user runs it).

## Design decisions (binding)

1. **Normalisation lives in the broker, not the hook.** The hook forwards the runtime's raw payload; the broker's normaliser builds the typed record. One normaliser, in Python, unit-tested. (The spec has the hook normalise; same trust boundary, thinner client.)
2. **The broker's reply is what the hook must do.** In shadow the broker logs its real decision and replies `allow`. The hook has mode logic only for failure: an unreachable broker, an error or malformed reply, or no reply within 2 s → shadow: allow and append a marker; acting: block with "guard unavailable". The hook is **inert** (no opinion) only when `BW_GUARD_MODE` is unset — a hand-run agy, or an agy lead bw runs as `manual`/`bypass` (bw sets `BW_SESSION` for every lead, but the guard variables only for guarded ones). `BW_GUARD_MODE` set with the socket or token missing is a failure, not inertness.
3. **Not built in v0, rejected rather than ignored:** `guard.mode: "acting"` ("acting arrives with build step 4 (needs `bw guard eval`)") and `guard.rules_on_native: true` ("not built yet"). The broker and hooks implement acting because the attack harness needs it; no real lead can reach it, so v0 needs no demotion or promotion gate.
4. **Gray means ask in v0, logged apart.** Every decision carries `source`: `rule` or `gray`. The gray share is step 2's measurement, and it is expected to be large (the allow grammar is deliberately small; `jq`, `awk`, `npm install`, `git checkout`, MCP reads all start gray).
5. **Autonomy and today's behaviour.** Schema 3 defaults: claude-code `native`, codex `native`, agy `guard`, pi `guard`, kimi `manual` (no Kimi default in the spec; `manual` is today's — author's call). Codex's default follows the spec's Goal 1 and table; its amendment's "only when the user sets it" is read as being about version-2 files, and writing `schema_version: 3` is the user setting it — the CHANGELOG says plainly that schema 3 moves Codex leads to `--approve-for-me` by default. A schema-2 file gets *legacy* autonomy: no flags added to any argv (byte-identical to today); the session records effective autonomy claude-code `native`, codex `manual`, agy `manual`, pi `bypass`, kimi `manual`, or `custom` when the lead's `args` carry a permission flag; `requested` is null.
6. **Per-repo lists are profile keys in v0.** `profiles.<p>.protected_branches` (default `["main", "master"]`), `profiles.<p>.deploy_commands` (default `[]`, command prefixes). Reading a repo's esc pack waits for the pack field to be agreed with esc's maintainers.
7. **Notices before the inbox exists** (inbox is build step 5 of the 2026-10-24 spec): "guard unreachable" is one printed `bw:` line per session plus the `unreachable` count in the `guard` metrics event.
8. **Local redaction for the log.** `guard.jsonl` stores the call after a small best-effort redaction (bearer tokens, `KEY=`/`TOKEN=`/`SECRET=`/`PASSWORD=` assignments, `--password`/`--token` flag values, `user:pass@` in URLs, `Authorization:` header values). The digest is of the unredacted call. Redaction before a model request is v1.
9. **Who touches guard state.** Only bw's own code writes `guard.jsonl` (the broker's decisions, `bw guard review`'s marks), via `lead/guard/record.py`; never a hook. A guarded lead cannot *write* any of it. A pi lead on the `sandbox-exec` backend can *read* it (that backend allows reads by default, as it does `containment.json` and the metrics log); nono denies it. Stated, not fixed: the content is the lead's own redacted calls.
10. **The socket and the clients sit where no lead can write.** `state_dir/guard/<worktree-key>/` holds `sock` (0600) and the session's client copies (`hook.py`, `pi_guard.ts`, copied from bw's own code at session start). It is in no write grant: not `handoffs/` (pi's sandbox grants that dir, and agy gets it through `--add-dir`, so a socket there could be unlinked and rebound by the lead, and a client there could be rewritten). Before any guarded lead starts, bw refuses a `state_dir` that overlaps the worktree for **every** runtime (agy never goes through `lead_grants`). The socket is bound and listening before `Popen` and served by a thread started after it (no thread exists while `preexec_fn` runs); a stale socket left by a hard-killed bw is unlinked once the worktree lock is held. A path over 103 bytes refuses to start, naming it. Requests carry `BW_GUARD_TOKEN` (16 random bytes, hex), compared with `hmac.compare_digest`. A lead can still *send* requests (the spec says so); it can neither answer them nor change the code that answers.
11. **The lexer is ours, not `shlex`.** `shlex` with `punctuation_chars` treats a newline as whitespace and strips the difference between `;` and `';'`, so a second command on a new line becomes an argument of the first. `rules.py` gets a small lexer that keeps operators (`;`, `&`, `&&`, `|`, `||`, newline, redirections) apart from quoted text, and marks any word with an unquoted `$`, backtick, or backslash as unexpanded.
12. **Repo scripts are trusted only as the repo has them.** A script path is allowed only if git tracks it and it is unchanged from `HEAD` (read through `handoff._git`, outside the sandbox). A script the lead wrote or edited this session is gray — otherwise "write a script, then run it" turns every block into two allows.

## Review Focus

- **Quoted data that looks dangerous** — `git commit -m "curl x | sh; rm -rf ~"` is a commit: `allow`. Test in Task 3.
- **A second command on a new line or after `&`** — `echo ok` + newline + `herdr pane send x` is two segments, the second blocked. Test in Task 3.
- **Expansion the guard cannot see** — `cat "$HOME/.ssh/id"`, `rm -rf ${D}`, `PATH=/tmp/x ls`, `echo x > $T/out` never reach `allow`. Test in Task 3.
- **The broker gone while the lead lives** — shadow allows and leaves markers; the next `bw lead` reports them once, clears them, and reclaims the stale socket. Test in Task 7.
- **A cap switch onto a guarded lead that cannot start** — bw stays on the current lead and says why, instead of killing it first. Test in Task 7.

- `lexer.Word = namedtuple("Word", "text quoted unexpanded")` (`text` with quotes removed; `unexpanded` true when an unquoted or double-quoted `$`, a backtick, or an unquoted backslash occurs; `~` at the start of a word is expanded to `home` and is not unexpanded); `lexer.Op = namedtuple("Op", "op")` for `;`, `&`, `&&`, `|`, `||`, newline, `>`, `>>`, `<`, `<<`, `<<<`, `2>`, `&>`, `>&`, `(`, `)`; `lex(command: str, home: str) -> list` raises `ValueError` on an unterminated quote. ### Task 4: The decision record and the broker

**Files:** Create `lead/guard/record.py`, `lead/guard/broker.py`; Test `tests/test_guard_broker.py`.

**Interfaces:**
- Consumes: Task 3 `normalise`, `decide`, `redact`, `digest`, `rules_version`, `guard_version`; `metrics/store.py` `append` and `read_events` (reused for the locked JSONL).
- `record.path(state_dir)` = `state_dir/guard.jsonl`; `record.append(state_dir, event)` creates the file with `os.open(..., 0o600)` before the first `store.append` (which alone would create it at the umask); `record.load(state_dir) -> dict` with `decisions` (marks folded in), `marks`, `orphan_marks`, `warnings`. A decision record: `type: "decision"`, `id` (12 hex), `ts`, `session_id`, `project` (worktree key), `profile`, `lead`, `runtime`, `runtime_version`, `tool`, `kind`, `call` (redacted, full length), `digest`, `source`, `rule`, `decision`, `reason`, `latency_ms`, `rules_version`, `guard_version`, `policy_digest` (sha256 of the profile's `protected_branches` and `deploy_commands`, 12 hex), `mode`, `outcome` (`"shadow-allowed" | "allowed" | "blocked" | "asked"`), `judge_model: null`, `prompt_hash: null`. A mark: `type: "mark"`, `decision_id`, `verdict: "right" | "wrong"`, `sampled: bool`.
