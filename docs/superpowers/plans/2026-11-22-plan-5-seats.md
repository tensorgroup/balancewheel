# Plan 5 — `seats/`: one Python runner behind `bw seat` — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

*Written 2026-11-22; revised the same day after a five-seat plan panel (rulings R1–R26, each marked
"(moderator's call, plan panel)" where it landed). Project 1 of the 2026-11-22 design (build order step 1). Project 2 (`panel/`) uses the
interfaces this plan fixes: `bw seat` and `seats.run.run_seat`, the session store, the cap flag,
`seat_items` and the seat verification store, and the `usage` event. Each Interfaces block that Project 2
reads is marked "(P2 contract)". Where this plan adds to or departs from the spec, the departure is a
numbered Design decision below.*

**Goal:** `bw seat <id> "prompt"` runs one read-only, blind, sandboxed seat with a brief, sessions, a cap,
a stand-in, and a usage record; `bw seat verify` proves each seat by attack and writes `state_dir/seats.json`;
`bw start` verifies seats whose keys changed, in the background after the lead opens, without the user asking.

**Architecture:** A new package `seats/` with one module per responsibility: `adapters.py` (headless argv
and output parsing per runtime), `brief.py`, `sessions.py`, `caps.py`, `run.py` (one run), `verify.py` (seat
key, pass store, `seats.json`, re-verification), `judge.py` (the attack's evidence judge), and `cli.py`
(`bw seat` argument parsing). `lead/sandbox.py` gains `seat_grants` beside `lead_grants`; the code-path lists
move to `lead/codepaths.py`, which both the lead key and the seat key hash. Every shell-out goes through
`lead.proc.run` or a `run=` parameter. `seats/` reaches `metrics/` the way `lead/` does: import `lead.paths`
first, then `import store`.

**Tech Stack:** Python 3.9+ standard library only (`typing.Optional`, no `X | None`); `fcntl`, `secrets`,
`hashlib`, `tempfile`; `/bin/bash` 3.2 for the attack script; `unittest`.

**Spec:** `docs/superpowers/specs/2026-11-22-seats-panel-guard-packs-design.md` — "Project 1 — `seats/`"
(all of it), "Constraints", "Build order", "Roadmap amendment", "Amendments to earlier documents" (the
`bin/seat`, `metrics/summary.py`, config schema 3, and reserved-name bullets), "Left to the builder", and
from Project 2's "Config" the `panel` object and the seat key `tier` (Design decision 1).

## Global Constraints

- Python 3.9+ standard library only. No YAML parser, no HTTP library.
- Tests: `python3 -m unittest discover -s tests -v` from the repo root. Tests are hermetic: they set
  `BW_STATE_DIR`, `BALANCEWHEEL_METRICS_LOG`, and `BALANCEWHEEL_CONFIG` to temp paths, and they spend no
  model quota. Anything that spends model quota lives in `tests/attack/` and is not in `unittest discover`.
- Privacy firewall: fixtures in `tests/fixtures/seats/` are synthetic and hand-written from the shapes
  that Task 2 records. Never paste captured CLI output, real paths, account names, or session ids.
- No preview model id in an interface. Model ids are config values; no code names one.
- `metrics/store.py` is the only appender to the metrics log (`store.append`).
- `bw` runs from a checkout no lead edits.
- New config keys go in the schema (`metrics/config.py`), in `balancewheel.example.json`, and in
  `CHANGELOG.md` `[Unreleased]` in the same commit.
- Any change to a `bw` command, a module, an adapter, or a config key also regenerates
  `docs/usage-map/data.generated.js` with `python3 docs/usage-map/generate.py` in the same commit.
- Commit summaries are lowercase with a `feat:` / `fix:` / `test:` / `docs:` prefix. Do not commit
  `.claude/` files.
- `bin/bw`'s module docstring is its help text and lists every subcommand.
- The brief reaches a seat by file or stdin, never on argv.
- A seat keeps write-capable tools. The OS sandbox is the only guard. Never remove tools to make an
  attack pass.
- Usage-limit matching reads error lines only, never the prompt echo.
- **Lead keys reset once.** Task 3 (`lead/codepaths.py`) and Task 4 (`lead/sandbox.py`) change every lead's
  containment and guard key. Run them back to back. No later task touches `lead/sandbox.py`,
  `lead/runtimes.py`, or `lead/codepaths.py`. The user re-verifies leads once, right after Task 4
  (Task 4, Step 7), so pi and Kimi leads keep working (moderator's call, plan panel).
- Exit statuses of `bw seat`: the CLI's own status; `124` on the wall-clock cap; `75` when bw refuses or
  cannot start the seat; `2` on a usage error or an unknown seat id.

## Design decisions (binding)

1. **`panel` and `tier` land here.** The spec puts the `panel` object and the seat key `tier` under
   Project 2's "Config", but a seat run needs `panel.cap_min` and `panel.deep_cap_min`, and `seat_items`
   and `bw seat list` need `tier`. This plan adds the whole `panel` object (all four keys, each an integer
   of at least 1) and `tier` in Task 5. Project 2 only reads them.
2. **The adapter has nine more fields than the spec lists** (`tool_results` too: the tool outputs the
   runtime reported, which the attack judge reads instead of model prose). A seat needs the final answer (`answer`), the
   error lines without the vendor's prompt echo (`errors`), the files the seat key manifests (`hook_files`),
   the login files a private home links to (`credentials`), the hostile project files present for this
   runtime (`project_code`), how the input reaches the CLI (`prompt_via`), the flags that make the CLI skip
   project config (`ignore_flags`, for the hostile positive control), and the env keys the seat needs
   (`env_keys`, Design decision 15).
3. **One input file, never argv.** `run.py` writes `<scratch>/input.md`: the brief and the reading rule
   (new session with a brief only), then the task. The adapter reads it on stdin (`prompt_via: "stdin"`)
   or gets a fixed one-line argv instruction to read that file (`prompt_via: "file"`). So neither the brief
   nor the task is on argv. `argv(seat, input_path, deep)` replaces the spec's `argv(seat, brief_path,
   prompt, deep)`.
4. **Project 2 resumes an exact session and reads an exact result.** `bw seat` gains `--session ID` (resume
   exactly that id), `--result F` (the run's result as JSON), and `--transcript F` (raw stdout and stderr,
   for the attack). The same run is a Python call, `seats.run.run_seat`, which Project 2's panel child
   calls in-process.
5. **The attack runs an unverified seat in an isolated state dir, through a per-seat token file**
   (moderator's call, plan panel: R1, R23, R25). `verify_seat` makes the attack's run dir
   `$HOME/.cache/bw-seat-attack/run.XXXXXX/` and its isolated state dir `<run>/state/`. It writes the token
   to `<run>/state/seats/attack-tokens/<seat>.json` (`{seat, token, expires}`, mode 0600). The script
   exports `BW_STATE_DIR=<run>/state` and `BALANCEWHEEL_METRICS_LOG=<run>/metrics.jsonl` (as
   `tests/attack/guard_attack.sh:39` does) and passes the hidden flag `--attack` (no value) to `bw seat`.
   `run_seat(attack=True)` skips the verification step only when the current state dir holds an
   unexpired token file for this seat. The token never travels on argv or in the env. The seat cannot
   read it: the state dir is read-denied. One file per seat, so two attacks at once keep both tokens.
6. **Failures persist apart from passes, and a later failure wins.** Passes go to
   `state_dir/seat-verify.json` through `containment.record_pass(..., store="seat-verify.json")` (keyed by
   seat id). The last failed probe per seat goes to `state_dir/seats/failures.json` (`{seat: {key, probe,
   ts}}`), written under an flock. A failure recorded after a pass under the same key revokes that pass
   (moderator's call, plan panel: R7). `seats.json` is derived from both and from the current keys,
   written under an flock, and lists enabled seats only (R16).
7. **Seat scratch dirs share one read-denied parent.** Seatbelt allows reads by default, so a seat could
   read another seat's scratch dir in the temp root. Every seat scratch dir is created under
   `<system temp root>/bw-seats/`. Every seat's profile denies reads under that parent and re-reads its
   own scratch dir (the inbox-view pattern). `seat_grants` takes the scratch dir as a fifth argument.
8. **The base has no integration-branch key.** `brief.resolve_base` tries, in order, the target of
   `refs/remotes/origin/HEAD`, then local `main`, then local `master`. With none, the brief says "base
   unknown; diff against HEAD" and diffs the working tree against `HEAD`.
9. **One usage row per run that happened** (moderator's call, plan panel: R9). The stand-in's row has
   `seat: <fallback>` and `stand_in_for: <original>`. The original gets a `ran: false, reason: "usage
   cap"` row only when it did not run (capped before start). An original that ran and hit the limit has
   its own `ran: true, reason: "usage cap"` row and no extra row.
10. **One run per seat and directory at a time.** The per-seat, per-directory lock is non-blocking. A held
    lock is exit 75 with reason `busy`. A run never waits for another.
11. **Codex `rate_limits` are parsed, not stored.** `run_seat` returns them in the result. Writing the `cli`
    quota snapshot is Project 3.
12. **The seat attack has its own timeout.** `lead.verify._attack` gains `timeout=ATTACK_TIMEOUT`. A seat
    attack passes `2 * panel.deep_cap_min * 60 + 300` seconds (fresh, resumed, hostile).
13. **The CLI's output files live in the seat's scratch dir** (moderator's call, plan panel: R3). Node
    aborts at startup when stdout or stderr is a file outside the sandbox's write grants
    (`tests/attack/guard_attack.sh:85`). `lead.proc.run` gains `out_dir=None`; with it, the stdout and
    stderr temp files are made with `tempfile.TemporaryFile(dir=out_dir)`. `run_seat` passes the scratch
    dir, which the seat profile grants. Every fake `run` in tests accepts `out_dir`.
14. **Seat attacks never block the lead** (moderator's call, plan panel: R12; a spec change). `bw start`
    opens the lead first. Then it starts one detached `bw seat verify --changed` child for the seats whose
    keys have no pass, and prints one line. A seat still unverified when a panel needs it is `absent:
    "unverified"`, and the panel starts its verification with `verify.spawn_verify` and does not wait.
15. **The seat env is an allowlist** (moderator's call, plan panel: R13; a spec change). Only `PATH`,
    `HOME`, `TMPDIR`, `LANG`, `TERM`, `LC_*`, and the keys the adapter declares in `env_keys` reach the
    seat.
16. **Inside the seat home, code paths stay read-only** (moderator's call, plan panel: R14, R11; a spec
    change). Each adapter's grants deny writes to the runtime's code-loading names inside the seat home
    (hooks, settings, extensions, MCP config). The seat's own session store stays writable, so resume
    works. A credential file the CLI refreshes is writable as that one file only (a `literal` rule).
    bw's own writes into a seat home use `O_NOFOLLOW` and refuse a symlinked dir (R15).

## Review Focus

- **The seat's CLI is missing or prints no version** (not installed, PATH lacks it, a broken update) —
  `bw seat` exits 75 with reason `unverified: <runtime> version unreadable`, and `bw start` shows the seat
  as `pending: version unreadable` in `bw seat verify`. Nothing raises. Test in Task 11 and Task 13.
- **A fallback chain or cycle under caps** (`astra → gem`, `gem` also capped; or `a → b → a`) — one hop
  only, then exit 75 with reason `usage cap`, no loop, and every seat that did not run has a `ran: false`
  row. Test in Task 11.
- **A target repo with no remote, a detached HEAD, no commits yet, or a shallow clone** — the brief still
  builds and says what base it used. Test in Task 7.
- **Two runs of the same seat in the same dir at once** (a panel and a hand run) — the second exits 75 with
  reason `busy`; the session store stays valid JSON with the first run's id. Test in Task 6 and Task 11.
- **Ctrl-C or SIGTERM during a run** — the CLI's process group is killed, the scratch dir is gone, one
  usage row with `ok: false, reason: "interrupted"` is written, and the exception goes up. Test in Task 11.
